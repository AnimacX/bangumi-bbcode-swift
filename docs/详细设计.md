## 3. 核心解析引擎

### 3.1 BBCode 入口 (`BBCode.swift`)

```swift
public class BBCode {
    let tagManager: TagManager
    public init()                    // 初始化并加载内置标签
    public func validate(bbcode: String) throws  // 仅验证不渲染
}
```

`validate()` 解析 BBCode 并在遇到错误时 `throw`，用于预验证。

**BBCodeError 枚举（6 种错误）：**

| 错误 | 触发器 |
|------|--------|
| `.internalError(String)` | 状态机内部异常 |
| `.unfinishedOpeningTag(String)` | `[tag` 后遇到 EOF |
| `.unfinishedClosingTag(String)` | `[/tag` 后遇到 EOF |
| `.unfinishedAttr(String)` | `[tag=val` 后遇到 EOF |
| `.unpairedTag(String)` | `[/tag]` 与当前开标签不匹配 |
| `.unclosedTag(String)` | 在不能含换行的标签内出现换行 |

### 3.2 状态机 (`Parser.swift`)

```swift
enum Parser {
    case content
    case tag
    case tagClosing
    case attr
    case smilies
}
```

每个 case 实现方法：
```swift
func parse(_ g: inout String.UnicodeScalarView.Iterator, _ worker: Worker) -> Parser?
```

返回 `nil` 表示 EOF 到达，解析结束。返回 `.content` 为最常见的状态转换。

**Node 类（AST 节点）：**
```swift
class Node {
    var children: [Node]           // 子节点列表
    weak var parent: Node?         // 父节点（弱引用，避免循环）
    var value: String              // 标签名或文本内容
    var attr: String               // 属性值（如 URL、颜色值）
    var paired: Bool               // 闭标签是否匹配（true = 已完成配对）
    var type: BBType               // 节点类型
    var description: TagDescription?  // 标签行为描述
}
```

**Worker 类（解析上下文）：**
```swift
class Worker {
    let tagManager: TagManager
    var currentNode: Node       // 当前正在构建的节点
    var rootNode: Node          // 根节点
    var error: BBCodeError?     // 解析错误
    func parse(_ bbcode: String) -> Node?  // 主循环
}
```

`Worker.parse()` 主循环：
1. 创建 `rootNode`（类型 `.root`，`paired=true`）
2. 用 `UnicodeScalarView.Iterator` 迭代字符
3. 从 `.content` 状态开始，循环调用 `parser.parse(&g, self)`
4. 状态返回 `nil` 时结束
5. 检查 `currentNode === rootNode && currentNode.paired` 确认解析成功

**错误报告辅助函数：**
- `unclosedTagDetail(unclosedNode:) -> String` — 重建未闭合标签的 BBCode 源码
- `nodeContext(node:) -> String` — 递归重建节点的 BBCode 源码

### 3.3 标签系统 (`Tags.swift`)

**BBType 枚举：**

```swift
enum BBType: Int {
    // 结构类 (case 0-4)
    case root, plain, br, paragraphStart, paragraphEnd
    // 布局类 (5-8)
    case center, left, right, align
    // 容器类 (9-10)
    case quote, code
    // 链接/媒体类 (11-13)
    case url, image, photo
    // 文本样式类 (14-21)
    case bold, italic, underline, delete, color, size, mask, ruby
    // 列表类 (22-23)
    case list, listitem
    // Bangumi 专有 (24-27)
    case bgm, bmo, subject, user
    // 不支持 (28-30)
    case background, avatar, float
    // 哨兵 (31)
    case unknown

    // 分组数组（用于 allowedChildren 白名单构造）
    static let unsupported: [BBType] = [.background, .avatar, .float]
    static let layout: [BBType] = [.center, .left, .right, .align]
    static let textStyle: [BBType] = [.bold, .italic, .underline, .delete, .color, .size, .ruby]
}
```

**TagDescription 结构：**
```swift
struct TagDescription {
    let tagNeeded: Bool          // 是否需要闭标签
    let isSelfClosing: Bool      // 是否自闭合 (<br>, [*], [bgm], [bmo], [plain])
    let allowedChildren: [BBType]?  // nil=禁止子标签, [] 或 [.xxx]=白名单
    let allowAttr: Bool          // 是否允许 [tag=value] 语法
    let isBlock: Bool            // 是否块级元素（影响段落处理）
}
```

**TagInfo 结构：**
```swift
struct TagInfo {
    let label: String            // BBCode 标签名, e.g. "b", "img", "url"
    let type: BBType             // 枚举类型
    let desc: TagDescription     // 行为描述
}
```

**TagManager 类：**
```swift
class TagManager {
    let tags: [TagInfo]
    init(tags: [TagInfo])        // 按 label 长度降序排列
    func getType(str: String) -> BBType?
    func getInfo(str: String) -> TagInfo?
    func getInfo(type: BBType) -> TagInfo?
}
```

按 `label.count` 降序排列确保 `"float"` 优先于 `"b"` 匹配。

### 3.4 State: content (`ContentParser.swift`)

```swift
func parseContent(_ g: inout Iterator, _ worker: Worker) -> Parser?
```

**职责：** 扫描纯文本内容，是状态机的主入口状态。

**核心逻辑：**
1. 创建新的 `.plain` 子节点
2. 逐字符读取：
   - `\r` 或 `\n`（换行符）：
     - 当前节点允许 `.br` → 创建 `<br>` 节点
     - 当前节点是 `.code` → 追加到纯文本内容
     - 其他 → 抛出 `.unclosedTag` 错误
   - `[`（开括号）：
     - 当前节点非 nil `allowedChildren` → 切换到 `.tag`
     - 当前节点 `paired==false` → 切换到 `.tag`（处理自闭标签边界）
     - 否则 → 作为普通文本 `[`
   - `(`（左括号）：
     - 切换到 `.smilies`
   - 其他字符：追加到当前纯节点值
3. EOF 时若当前节点非 root → 弹出到父节点并返回 `.content`（自动闭合）

**换行合并：** 连续的 `\r\n` 或 `\r` + `\n` 组合会被检测，`\r\n` 被当作单个换行。

### 3.5 State: tag (`TagParser.swift`)

```swift
func parseTag(_ g: inout Iterator, _ worker: Worker) -> Parser?
```

**职责：** 解析开标签 `[tagname]` 或 `[tagname=attr]`。

**核心逻辑：**
1. 创建 `.unknown` 节点
2. 逐字符读取：
   - 首字符是 `/` 且当前节点未配对 → 切换到 `.tagClosing`；否则 → `restoreNodeToPlain()`
   - `=`：查询标签名 → 校验 `allowAttr` → 切换到 `.attr`
   - `]`：查询标签名 → 检查 `isSelfClosing` → 若不自闭则设 `paired=false` 并推入 `currentNode`
   - `[`（嵌套）：将之前的 `[` 还原为纯文本，重试解析
   - 其他字符：累积为标签名（最大 8 字符；超过则转为纯文本）

**核心校验（`]` 路径）：**
```swift
if let tag = worker.tagManager.getInfo(str: newNode.value) {
    newNode.setTag(tag: tag)
    if let allowedChildren = worker.currentNode.description?.allowedChildren,
       allowedChildren.contains(newNode.type) {
        // 标签合法，接受
    } else {
        // 不在白名单内 → restoreNodeToPlain()
    }
}
```

**`restoreNodeToPlain()` 辅助函数：** 将失败的标签节点转为 `.plain` 类型，在前方插入 `[` 字符，将整个标签语法保留为可见纯文本（容错降级）。

### 3.6 State: tagClosing (`TagClosingParser.swift`)

```swift
func parseTagClosing(_ g: inout Iterator, _ worker: Worker) -> Parser?
```

**职责：** 解析闭标签 `[/tagname]`。

**核心逻辑：**
1. 逐字符读取构建闭标签名
2. 遇到 `]`：
   - 标签名匹配 `currentNode.value` → 设置 `paired=true`，弹出父节点
   - 标签名是当前节点的合法子标签 → 静默返回 `.content`（容错未配对内部标签）
   - 都不匹配 → 将 `[/tagname]` 还原为纯文本
3. 遇到 `[` 或 `=`：无效语法 → 还原为纯文本

### 3.7 State: attr (`AttrParser.swift`)

```swift
func parseAttr(_ g: inout Iterator, _ worker: Worker) -> Parser?
```

**职责：** 读取标签属性值（`=` 和 `]` 之间的部分）。

简单扫描：逐字符读取 → 累积到 `worker.currentNode.attr` → 遇 `]` 返回 `.content`。EOF 或换行触发 `.unfinishedAttr` 错误。

属性值原样存储在节点上，在渲染时解析（如颜色名、URL 等）。

### 3.8 State: smilies (`SmiliesParser.swift`)

```swift
func parseSmilies(_ g: inout Iterator, _ worker: Worker) -> Parser?
```

**职责：** 解析 Bangumi 特有的 `(bgmNNN)` 贴纸和 `(bmoC...)` 表情。

**核心逻辑：**
1. 创建 `.unknown` 节点
2. 读取最多 100 字符找 `)`
3. 遇到 `)`：
   - **BMO**: 内容以 `"bmo"` 开头 → `.bmo` 节点，完整编码为 attr
   - **BGM**: 正则 `#"(?<id>\d+)"#` 匹配 → 验证 ID 范围（1-125、200-238、500-529）→ `.bgm` 节点，数字 ID 为 attr
   - 其他：还原为纯文本（重新插入 `(`）
4. 换行、超过最大长度、EOF 无 `)`：还原为纯文本

**`restoreSmiliesToPlain()` 辅助函数：** 将失败的表情节点转为 `.plain`，在前方插入 `(` 字符。

## 4. 渲染系统

### 4.1 HTML 渲染器 (`Renders/HTML.swift`)

**公开 API：**
```swift
extension BBCode {
    public func html(_ bbcode: String, args: [String: Any]? = nil) throws -> String
    // 便捷函数
    public func BBCodeToHTML(code: String, textSize: Int = 16) -> String
}
```

**后处理 -- 段落/换行处理 (`handleNewlineAndParagraph`)：**
1. 去除首尾 `<br>`（头部尾部空白修剪）
2. 在块级容器内，检测连续两个 `<br>`：第一个转为 `.paragraphEnd`(`</p>`)，第二个转为 `.paragraphStart`(`<p>`)
3. 单个 `<br>` 保持不变
4. 递归处理子节点

**`safeUrl(url:defaultScheme:defaultHost:)` — URL 安全过滤：**
给无协议/host 的 URL 补全默认值，阻止 `javascript:` 等危险协议。

**`String.stringByEncodingHTML` — HTML 实体编码：**
保护 CJK 字符范围免于编码（CJK 标点、统一汉字、全角格式、B-E 扩展区），同时编码控制字符和标准 HTML 实体。

**htmlRenders 字典 — 按 BBType 的渲染闭包（部分列举）：**

| BBType | HTML 输出 |
|--------|----------|
| `.plain` | HTML 编码的 value |
| `.br` | `<br>` |
| `.paragraphStart` | `<p>` |
| `.paragraphEnd` | `</p>` |
| `.center/.left/.right` | `<p style="text-align:...">` |
| `.align` | 根据 attr 映射到 left/right/center |
| `.list` | `<ul>` 或 `<ol>`（attr 非空） |
| `.listitem` | `<li>` |
| `.bold` | `<strong>` |
| `.italic` | `<em>` |
| `.underline` | `<u>` |
| `.delete` | `<del>` |
| `.color` | `<span style="color:...">`（校验颜色名/hex） |
| `.size` | `<span style="font-size:...px">` |
| `.mask` | `<span class="mask">`（CSS hover 显示） |
| `.code` | `<div class="code"><pre><code>` |
| `.quote` | `<div class="quote"><blockquote>` |
| `.url` | `<a href="..." target="_blank" rel="nofollow external noopener noreferrer">` |
| `.image` | `<img src="...">`（attr 含宽高 `w,h`） |
| `.photo` | `<img src="https://lain.bgm.tv/pic/photo/l/{attr}">` |
| `.subject` | `<a href="https://bgm.tv/subject/{value或attr}">` |
| `.user` | `<a href="https://bgm.tv/user/{value或attr}">@{value或attr}</a>` |
| `.bgm` | `<img src="https://lain.bgm.tv/img/smiles/{范围路径}/{id}.{ext}">` |
| `.bmo` | base64 Data URL 的 PNG（通过 `BmoRenderer.renderCGImage`） |
| `.ruby` | `<ruby>base<rt>annot</rt></ruby>` |
| `.background/.avatar/.float` | 空字符串（剥离不支持标签） |

**`BBCodeToHTML()` — 完整 HTML 文档包装器：**
将 BBCode HTML 输出包装为完整 HTML 页面，含 `<head><style>` 中的全套 CSS：
- Dark/Light 模式（`prefers-color-scheme`）
- 代码块样式（等宽字体、圆角边框、横滚动）
- 引用块样式（左边框、半透明背景）
- 遮罩 hover 显示样式
- 图片和列表样式

### 4.2 纯文本渲染器 (`Renders/Plain.swift`)

**公开 API：**
```swift
extension BBCode {
    public func plain(_ bbcode: String, args: [String: Any]? = nil) throws -> String
}
```

**plainRenders 字典 — 按 BBType 的渲染规则：**
- `.br` → 空格 `" "`
- `.paragraphStart`/`.paragraphEnd` → 空字符串
- `.mask` → 内容长度个 `"■"`（黑方块替代）
- `.ruby` → `"base(annotation)"` 格式
- `.code`, `.quote`, `.subject`, `.user`, `.url`, `.image`, `.photo`, `.bgm`, `.bmo`, `.list`, `.listitem` → 空字符串（剥离）
- 所有文本样式标签 → 仅渲染内部子内容，剥离格式

### 4.3 SwiftUI Text 渲染器 (`Renders/Text.swift`)

**内部 API（同模块调用）：**
```swift
extension BBCode {
    func text(_ bbcode: String, args: [String: Any]? = nil) -> TextView  // @MainActor
}
```

**TextView 枚举（三种渲染结果）：**
```swift
enum TextView {
    case view(AnyView, BBType?)     // 完整 SwiftUI View（图片、代码块、引用）
    case text(Text)                 // SwiftUI Text（格式化文本）
    case string(AttributedString)   // 属性字符串（纯文本带链接）
}
```

**后处理 -- 换行处理 (`handleTextNewlines`)：**
比 HTML 版本简单：
1. 去除首尾 `<br>`
2. 将块级元素后的 `<br>` 转为纯文本（避免多余空行）
3. 递归处理子节点

**渲染子节点合并逻辑 (`renderInnerText`)：**
递归渲染子节点，然后合并连续的 `.string` 片段以最小化视图数量：
1. 连续 `.string` → 拼接为一个 `AttributedString`
2. 遇到 `.text` → 累积的字符串生成一个 `Text` 加入数组
3. 遇到 `.view` → 累积的文本生成一个 `AnyView`（`VStack`），加入视图数组
4. 最终返回 `.view`（`VStack` 含所有子视图）、`.text`（拼接后的 `Text`）或 `.string`（拼接后的 `AttributedString`）

**textRenders 字典 — 按 BBType 的渲染规则（部分列举）：**

| BBType | SwiftUI 渲染 |
|--------|-------------|
| `.plain` | `AttributedString(n.value)` |
| `.br` | `AttributedString("\n")` |
| `.bold` | `.bold()` 修饰符 |
| `.italic` | `.italic()` 修饰符 |
| `.underline` | `.underline()` 修饰符 |
| `.delete` | `.strikethrough()` 修饰符 |
| `.color` | 通过 `Color(n.attr)` 解析颜色 → `.foregroundColor()` |
| `.size` | `.font(.system(size:))`，限制范围 8-50px |
| `.code` | `AnyView`：等宽字体 `.code` 分块，圆角边框 |
| `.quote` | 卷曲引号 `\u{201C}`/`\u{201D}` 包裹，内容颜色变暗，传递 `inQuote=true` 参数 |
| `.url` | `Link(destination:)` 带 BGMTV 蓝色 |
| `.subject` | `Link(destination: "https://bgm.tv/subject/N")` |
| `.user` | `Link(destination: "https://bgm.tv/user/N")` 带 `@` 前缀 |
| `.image` / `.photo` | `ImageView(url:)` — SDWebImage 加载；**若 `inQuote=true` 则降级为 `[图片]` 文本** |
| `.mask` | `MaskView { ... }` — 点击显示遮罩内容 |
| `.ruby` | 基文本 + 上标 `(注音)` |
| `.bgm` | 从本地 Bundle 加载 PNG/GIF 资源（含 ID 范围回退逻辑） |
| `.bmo` | `BmoRenderer.renderImage(from:)` 渲染为 SwiftUI `Image` |
| `.list` | `VStack` + `.padding(.leading, 12)` |
| `.listitem` | 前置 `\u{2022}` (•) 符号 |
| `.background/.avatar/.float` | 空视图 |

**`inQuote` 机制：**
在 `[quote]` 内部渲染时，传递 `args["inQuote"] = true`。嵌套的 `[img]`/`[photo]` 渲染器检查此标志：
- `true` → 渲染为 `[图片]` 文本占位符（避免引用嵌套中加载过多图片）
- `false`/未设置 → 正常加载图片

### 6.3 平台差异说明

#### macOS 独有功能
1. **NSSavePanel** — 图片通过原生保存对话框保存到文件系统
2. **MaskView Hover** — 通过 `onHover` 修饰符实现鼠标悬停显示遮罩内容（需 `MaskContext.enableHovering = true`）
3. **Sheet 而非 FullScreenCover** — 全屏图片预览使用 `.sheet` 而非 `.fullScreenCover`

#### iOS 独有功能
1. **BBCodeUITextView** — 通过 `NSAttributedString` 的 HTML 文档类型初始化渲染 BBCode，适合需要 UITextView 行为的场景
2. **BBCodeWebView** — 通过 `WKWebView` 渲染完整 HTML 页面，支持完整 CSS/JS 样式
3. **FullScreenCover** — 全屏图片预览使用 `.fullScreenCover`
4. **UIImageWriteToSavedPhotosAlbum** — 图片直接保存到系统相册
5. **TabBarMinimizeBehavior** — 在未来的 iOS 26 上支持 tab 栏滚动最小化

#### tvOS
- 无法使用 `UITextView` / `WKWebView` 方案
- 仅 `BBCodeView` 可用（SwiftUI 原生方案）
- 图片保存功能不可用（无 UIKit 相册访问权限，无 AppKit 保存面板）

#### watchOS
- 仅 `BBCodeView` 可用，适合简单文本渲染
- 图片功能依赖 SDWebImageSwiftUI（异步加载可用）

#### visionOS
- 相当于 iPadOS 行为：使用 `.sheet` 而非 `.fullScreenCover`
- `canImport(UIKit)` 匹配 → 图片 API 使用 UIKit 变体

### 6.4 资源加载的跨平台处理

`Image(packageResource:ofType:)` 扩展：
- `.init(packageResource: "bgm15", ofType: "gif")` 从 SPM 模块 bundle 加载
- iOS/tvOS/watchOS/visionOS：`UIImage(named:in:with:)`
- macOS：`NSImage(contentsOf:)` — 路径不同：`Bundle.module.path(forResource:ofType:)`

## 8. BMO 表情系统

### 8.1 编码格式

BMO 编码格式（Bangumi 官方）：
```
(bmoC<base64url>)    — 紧凑编码
(bmo<category>:<id>,<category>:<id>,...)  — 传统格式
```

**紧凑编码解码流程：**
1. 剥离括号，检测 `bmoC` 前缀
2. Base64URL 解码 → 字节数组
3. VarUint 读取下一个部件的 `compactId`
4. 根据标志位读取修饰符（最多可选 7 项）：
   - 色调偏移 (Hue, 0-360°)
   - 亮度 (Lightness, 0-255)
   - 饱和度 (Saturation, 0-255)
   - X 偏移
   - Y 偏移
   - 变换掩码 (翻转/旋转)
   - 额外 JSON 数据
5. ZigZag 解码处理负值
6. 在所有类别中线性扫描 `findItemByCompactId` 找到对应部件

### 8.2 渲染管线

**BmoRenderer 渲染步骤：**
1. 解码 BMO 编码 → 部件列表
2. 创建 `CGContext` 位图（500×500 基础尺寸，`scaleAware` 适配 Retina）
3. 排序部件（按 `zIndex`）
4. 逐部件渲染：
   a. 从 bundle 加载 PNG → `CGImage`
   b. 应用颜色调整：`CIHueAdjust` + `CIColorControls`（饱和度/亮度）
   c. 应用变换掩码：水平/垂直翻转、0/90/180/270 度旋转
   d. 绘制到 `CGContext`
5. 输出 `CGImage` 或 SwiftUI `Image`

### 8.3 本地资源结构

```
Resources/Bmo/
├── manifest.local.json   # 部件清单：类别、ID、名称、图层、选择约束
├── f1.png ... f5.png     # 脸 (face)
├── m1.png ... m23.png    # 嘴 (mouth)
├── e1.png ... e25.png    # 眼 (eyes)
├── a1.png ... a21.png    # 配件 (accessories)
└── o1.png ... o19.png    # 其他 (others)
```

## 12. 已知设计约束

1. **标签名最大 8 字符：** `TagParser` 硬编码限制标签名长度，超过视为普通文本
2. **BGM ID 范围硬编码：** 1-125、200-238、500-529 范围写死在 `SmiliesParser` 中，新增范围需修改源代码
3. **BMO 编码最大 100 字符：** `SmiliesParser` 限制 `(` 到 `)` 之间的内容最多 100 字符
4. **`text()` 方法为 internal：** `BBCode.text()` 未声明 `public`，外部模块不能直接调用；需通过 `BBCodeView` 包装
5. **不支持 `[email]` 标签：** README 标明该标签为待实现
6. **`background`/`avatar`/`float` 标签不支持：** 解析时自动剥离，渲染时产生空输出
7. **`inQuote` 图片降级仅 Text 渲染器实现：** HTML 和 Plain 渲染器不检查 `inQuote`，quote 内的图片正常渲染
